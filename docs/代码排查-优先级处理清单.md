# EasyBake 代码排查 · 优先级处理清单

> 排查范围：`src/`（前端 ~390 个 TS 文件）、`server/`（auth BFF + PocketBase 扩展）、部署脚本与配置、PocketBase 集合规则文档。
> 排查方式：三路并行审计（服务端安全 / 前端正确性 / 部署与配置），P0 级发现均已由我逐条核对源码确认。
> 标注说明：✅ = 已核实源码属实；⚠️ = 逻辑成立，建议你复核运行环境后确认。

## P0 · 立即处理（影响财务数字正确性 / 已造成线上故障）

### P0-1 ✅ 列表查询默认静默截断 200 条，财务与库存会随数据增长漏算
- 位置：`src/services/pocketbase-rest/pocketBaseRestClient.utils.ts:5`、`src/services/pocketBaseRestClientCore.ts:54-56, 123-129`
- 问题：不传 `limit` 时 `requestedLimit` 默认等于页大小 200，取满第一页即返回，分页循环永远不翻页。财务台账、成本核算、`roast_batches`、采购批次、`app_settings` 的查询全部不传 limit。
- 后果：支出/收入记录超过 200 条后，财务总览"全部花费 / 经营利润"静默漏算多出的记录，无任何报错；采购批次超 200 条时生豆聚合出 `remaining=0`。`delete(collection, {match})` 先查后删，匹配超 200 条时只删 200 条，级联删除不完整。
- 修复：区分"取全部"与"取前 N 条"两种语义——不传 limit 时应持续翻页直到 `items.length < perPage`；同时修掉 `limit: 0` 返回空数组的语义陷阱。

### P0-2 ✅ 烘焙记录的"本次最终定价"从未参与收入计算
- 位置：`src/modules/finance/services/financeProfitCalculation.service.ts:86`、`financeOverview.service.ts:123`
- 问题：表单承诺"本次最终定价只影响本次烘焙记录收入"，`finalSaleUnitPrice` 也确实存进了批次，但全部财务计算用的都是生豆默认价 `defaultSaleUnitPrice`，该字段只有熟豆镜像在读。
- 后果：特价 ¥50 卖出的豆子按默认价 ¥80 计收入，"已实现收入/利润"直接虚高；反之则漏记。财务模块核心数字错误。
- 修复：收入计算处优先取 `batch.finalSaleUnitPrice ?? bean.defaultSaleUnitPrice`。

### P0-3 ✅ 收入列表接口出错时静默返回空数组并覆盖缓存，收入"凭空消失"
- 位置：`src/modules/finance/services/financeLedger.service.ts:306-317`，配合 `appDataRefresh.service.ts:226`
- 问题：收入列表 catch 一切错误后 `setCurrentIncomeRecords([]) + return ok([])`，随后刷新逻辑把空数组写进查询缓存；支出走抛错分支，唯独收入被静默清空。
- 后果：一次网络抖动即可让财务页手工收入全部归零且无提示，realtime/切页反复刷新会不断用空数组冲掉正确数据，利润被系统性低估。
- 修复：失败时抛错或保留上一次数据 + 显式错误提示，禁止用空数组覆盖缓存。

### P0-4 ✅ 部署产物权限未归一化（本次 landing.html 403 的根因，会复发）
- 位置：`deploy.sh:325, 344, 458`
- 问题：`cp -R` + `rsync -az` 全程保留本地文件权限，脚本只对目录本身 `chmod 755`，从不递归处理文件。任何本地权限为 600 的文件（协作工具写入、umask 差异）都会原样上线，Nginx 读不了 → 403。
- 修复：`rsync` 加 `--chmod=D755,F644`（前端 L325 与 BFF L246 都加），或在密钥扫描前 `chmod -R u=rwX,go=rX "${FRONTEND_RELEASE_DIR}"`。

## P1 · 尽快处理（安全边界 / 数据丢失风险）

### P1-1 ✅ `/internal/*` 内部端点的"回环校验"在 Nginx 反代后完全失效
- 位置：`server/auth-bff/unverified-user-cleanup-handler.ts:17-21`、`ai/roast-training-quality-handler.ts:13-17`、`router.ts:68-80`
- 问题：BFF 监听 127.0.0.1，经 Nginx 转发的所有外部请求 `remoteAddress` 恒为回环地址，`isLoopbackRequest` 对谁都放行。若 Nginx 把 `/internal/` 也转发，任何匿名用户 POST 一下即可用超管令牌批量删除超 24h 未验证账号。
- 修复：改用共享密钥请求头（如 `X-Internal-Token`）校验；同时在 Nginx 明确 `location /internal/ { deny all; }` 双保险。⚠️ 请顺手确认当前 Nginx 是否已屏蔽该路径。

### P1-2 ⚠️ 登录/注册限流信任 `x-real-ip` 请求头，可被伪造绕过
- 位置：`server/auth-bff/auth-rate-limit.ts:36-48`
- 问题：反代后恒以 `x-real-ip` 作为限流键。若 Nginx 没有强制 `proxy_set_header X-Real-IP $remote_addr`（覆盖而非透传），攻击者每次带随机 IP 头即可绕过 8 次/15 分钟限流暴力破解，还能撑满 10000 条计数挤掉合法用户。
- 修复：核实 Nginx 配置强制覆盖该头；BFF 侧可再加账号维度限流兜底。

### P1-3 ✅ 密钥扫描护栏存在 4 条绕过路径
- 位置：`deploy.sh:61-124, 246, 461-462`
- 问题：① 只检查 shell 环境变量，`.env` 文件里的 `VITE_*` 密钥照样打进 bundle；② marker 匹配的是变量名而 bundle 里泄露的是值；③ `grep -I` 跳过二进制/预压缩产物；④ BFF 在扫描之后才构建，从未被扫描。
- 修复：对 dist 做"值级"扫描（遍历本机 `.env*` 中敏感变量的值逐一 grep）；去掉 `-I`；BFF 构建移到扫描前并纳入范围。

### P1-4 ✅ 售出份数超过模板容量时，整锅收入静默从财务中消失
- 位置：`src/modules/finance/services/financeProfitCalculation.service.ts:142-144`
- 问题：`saleUnitCount > maximumSoldUnitCount` 时整个批次返回 null。表单只能拦当下，事后修改成本模板（脱水率/单份克重）导致容量下降时，历史批次的收入、成本、利润全部无声蒸发。
- 修复：超容量时按实际售出数照常计算并标记异常提醒，而非整体剔除。

### P1-5 ✅ 删除生豆是无事务的 6+ 步客户端级联删除，中途失败留下"僵尸数据"
- 位置：`src/modules/bean/services/bean-service/bean.service.inventory-repository.ts:493-527`
- 问题：串行删除烘焙批次→采购批次→烘焙记录→…→生豆本体，任一步断网即半删：库存显示 0、调整库存报错、财务采购支出消失，且 UI 回滚缓存与远端状态脱节。
- 修复：优先在服务端（PocketBase 扩展里已有事务能力）做级联删除；短期至少加失败续删/补偿与明确的"删除未完成"提示。

### P1-6 ✅ "本地备份已保留"提示是假的，备份服务为空实现
- 位置：`src/shared/services/submissionBackup.service.ts:6-13`；提示文案在 `RoastPage.tsx:240`、ProductionPage
- 问题：save() 只打了一行 debug 日志，IndexedDB 草稿缓存从未接线，但失败提示告诉用户"本地备份已保留，请检查后重试"。
- 后果：用户信了提示关掉抽屉，长文编辑内容永久丢失。
- 修复：短期先改文案删掉"备份已保留"；中期真正接上 IndexedDB 草稿保存。

### P1-7 ✅ 成本核算记录自相矛盾：利润按实际价算，存库却存建议价
- 位置：`src/modules/finance/services/finance.service.ts:88, 188, 210`
- 问题：`profit_per_sale_unit` 用用户实际输入价计算，`sale_unit_price` 字段却写入建议价，历史记录 profit ≠ price − cost，对不上账。
- 修复：统一存 `effectiveSaleUnitPrice`。

### P1-8 ✅ 账号注销遗漏多张含用户数据的集合，"所有关联数据已删除"不实
- 位置：`server/auth-bff/account-handler.ts:54-72, 126`
- 问题：删除清单缺 `roast_curve_records`（完整曲线）、`roaster_models`、`roast_training_samples`（含批次/曲线/生豆完整快照）、`roast_training_uploads`。
- 后果：注销后个人数据仍留存，构成隐私/合规问题与虚假告知。
- 修复：补全删除清单；训练快照类数据优先处理。

## P2 · 排期处理（正确性细节 / 纵深防御）

### 前端
1. ✅ **除零产生 Infinity**：存储层 schema 对 `dehydrationRate`/`saleUnitWeightGrams` 无边界校验，`saleUnitWeightGrams=0` 时预估收入变 Infinity 污染总览（`settings/schemas/index.ts:84,93` + `financeProfitCalculation.service.ts:70`）。存储 schema 补 min/max。
2. ✅ **1 克兜底出荒谬数字**：脱水率 100% 时产出重量兜底为 1g，每公斤成本算出几万元（`finance.service.ts:84-97`）。应报错而非兜底。
3. ✅ **采购日期未归一化**：`purchaseDate` 带时间串与纯日期串比较，"今日/本周"漏记当天买豆支出（`financeOverview.service.ts:271,448`）。统一走 `getFinanceDateTextFromTimestamp`。
4. ✅ **烘焙 mutation 不失效生豆缓存**：创建/删除批次会扣还库存，但从不 `invalidateQueries(beanQueryKeys)`，realtime 断线后库存长期陈旧（`useRoastBatches.ts:37-144`）。
5. ✅ **成本模板"后写覆盖"**：远端为空/推送失败后，下次拉取用默认值整体覆盖本地新建模板，无合并（`costTemplateSync.service.ts:44-48`）。
6. ✅ **AI 推荐结果未经 zod 校验直接进表单**：`modifiedPlanJson.steps` 异常时提交崩溃 `values.steps.map is not a function`（`RoastPlanAiRecommender.tsx:123`）。复用 JSON 导入路径的 zod schema。
7. ✅ **收入明细口径不一致**：明细标签显示 `N份 × 单价`，金额却是扣费后净额；模板包装费与手工包装支出存在双扣风险（`financeOverview.service.ts:423, 292-300`）。统一口径并在 UI 注明。
8. ✅ **filter 转义漏反斜杠**（前后端同一缺陷）：`escapeFilterValue` 只转义引号，值以 `\` 结尾可破坏过滤器语义（前端 `pocketBaseRestClient.utils.ts:26-28`、后端 `record-utils.ts:5-7`）。同时转义 `\\`。
9. ✅ **未配置远端时烘焙记录仅存内存**：mock 仓库给出与远端一致的成功反馈，刷新即丢且无提示（`roastBatch.service.state.ts:27-33`）。

### 服务端 BFF
10. ✅ **多处路径拼接未 `encodeURIComponent`**：`roast-analysis-handler.ts:227` 等三处，用户可控 id 含 `?`/`../` 可打到非预期 PB 端点（仍在用户 token 下）。对齐其他已正确编码的调用点。
11. ✅ **顶层异常把 `error.message` 原样回传**：可能泄露内部主机/端口细节（`pocketbase-auth-bff.ts:75-80`）。统一通用文案 + 服务端日志。
12. ✅ **确认类端点无限流、注册密码无长度校验**：纵深防御补齐（`router.ts:182-189`、`auth-handlers.ts:67-126`）。
13. ✅ **AI 额度控制是进程内锁**：多实例部署或高并发可超额，单实例影响有限（`usage-service.ts:171-228`）。

### 部署与配置
14. ✅ **vite 开发配置四连**：缺 `.env` 时 `.trim()` 直接崩；代理 `secure:false` 关闭证书校验；默认代理目标是生产 API；`--host 0.0.0.0` 把指向生产的代理暴露到局域网（`vite.config.ts:38,42,85`、`package.json:8`）。共享网络下 ②+④ 组合接近 P1。
15. ✅ **部署锁无过期/接管机制**：断电残锁永久阻塞发布，"无 owner 锁"更是无法自愈（`deploy.sh:159-175, 221-235`）。加 stale 判定 + `DEPLOY_FORCE_UNLOCK`。
16. ✅ **BFF 切换非原子且回滚吞错**：`rm -rf` 后 `mv` 失败即服务目录被删空；回滚 `systemctl restart || true` 掩盖失败（`deploy.sh:271-288`）。改 releases+symlink 模式。
17. ✅ **update_community_qr.sh**：远端 /tmp 低熵可预测路径 + symlink 竞态（共享服务器上可被利用以 root 落文件）；变量拼接可逃逸引号（L13, 44, 50-51）。远端 `mktemp` + `printf %q`。
18. ✅ **curl 命令行明文密码**：`--user "$USER:$PASS"` 可被同机用户 `ps` 看到（`deploy.sh:54`）。改 stdin 传配置。
19. ✅ **`deploy_test.sh` 无条件 source 本地文件**：`.deploy_test.local` 被篡改即任意代码执行。改白名单解析。
20. ✅ **文档"留空"歧义可酿成事故**：PocketBase 导入 JSON 中空字符串 `""` = 完全公开，与 Dashboard"锁定"（null）语义相反；`ai_usage_limits/ai_usage_logs` 恰好没有 import.json 只能照文档手建，一步失误即 P0（`docs/pocketbase-server-setup.md:416-451`）。文档改为"保持锁定/null，严禁空字符串"并补齐 import.json。
21. ✅ **杂项**：`ai_roast_profiles` 的 listRule 允许匿名枚举 public_model 记录（确认是否有意）；`docs/pocketbase-server-setup.md:470` 泄露本机绝对路径。

## 值得保持的优点

- **PocketBase 集合规则完整**：20+ 业务集合五条规则均带 `owner = @request.auth.id` 隔离（BFF 代理不做归属兜底，安全性正是靠这层规则成立——所以上面第 20 条的文档歧义才值得认真对待）。
- **Go 扩展的授权与并发正确**：显式 owner 校验、事务、乐观版本锁、库存不足回滚、参数化查询。
- **发布流水线工程化程度高**：原子切换、自动回滚、三重线上探针、锁元数据、密钥护栏意识（尽管有绕过面）。
- **前端防御性解析扎实**：全仓无 `dangerouslySetInnerHTML`/`eval`，JSON 导入有完整 zod 校验，库存扣减用乐观锁 + 重试。
- **仓库零凭据落盘**：全仓扫描未发现任何真实密钥；`.gitignore` 覆盖全面。
